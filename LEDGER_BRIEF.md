# Ledger — Project Brief for Claude Code

## What This Is

Ledger is a household expense tracker built as a single self-contained HTML file. There are two versions:

- **`expense-tracker-clean.html`** — Michael's personal version (Michael & Lili)
- **`expense-tracker-template.html`** — Generic shareable template (Person 1 / Person 2, neutral categories)

Both files are fully self-contained — all CSS, JS, and HTML in one file. No build process, no dependencies to install. They run directly in a browser.

## How It's Deployed

- Hosted on **GitHub Pages** (free static site hosting via GitHub)
- Repository contains the HTML file(s) — pushing to GitHub automatically republishes the site
- URL format: `yourusername.github.io/ledger` (or a custom domain if configured)
- Both versions can be in the same repo — personal version as `index.html`, template as `template.html`
- Data is **not** stored in GitHub — GitHub just serves the HTML shell
- To publish a change: edit the file → `git add . && git commit -m "description" && git push`
- GitHub Pages picks up the change automatically within ~30 seconds

## Data Architecture

All data is stored in two places:

### 1. Browser localStorage
Every device has its own local copy. Keys use `l3_` prefix for personal version, `lt_` prefix for template.

Key data arrays:
- `txns` — all transactions
- `incomes` — income entries
- `savAccts` — savings accounts
- `contribs` — savings contribution log
- `uploads` — CSV import history
- `trash` — deleted transactions (kept 30 days)
- `learned` — merchant → category overrides (auto-learned from manual recategorization)
- `CATS` — custom expense categories (via `l3_cats`)
- `INCOME_TYPES_ARR` — custom income types
- `ACCT_TYPES_ARR` — custom savings account types
- `people` — people/cardholders (template only, via `lt_people`)

### 2. Google Sheets (via Apps Script)
A Google Apps Script web app acts as a REST API to a Google Sheet. The sheet has these tabs:
- Transactions, Learned, Income, Savings, Contributions, Uploads, Trash

**Push** = overwrite entire Sheet with local data  
**Pull** = replace all local data with Sheet data (always full replace, never merge)

The Apps Script URL is stored in `l3_sheets_url` / `lt_sheets_url`.

## Key Architecture Decisions

### Sync Rules
- Push always **overwrites** the entire Sheet — never appends
- Pull always **replaces** all local data — never merges
- Both operations require user confirmation for Pull
- Auto-push runs after every import and manual transaction add
- "Clear local data" button wipes localStorage only, Sheet is untouched

### Income Flagging
When a transaction is flagged as income from the Transactions page:
- `t.incomeType` is set on the transaction object (e.g. `'salary'`, `'rental'`, `'transfer'`)
- A corresponding entry is created in the `incomes` array with `fromTxnId` pointing back to the transaction
- Both fields must be saved/restored through Sheets for income to appear correctly
- **Critical**: `fromTxnId` and `category` must be included in the Income sheet write — this was a recurring bug

There is a **Repair missing income entries** button in Settings that scans transactions with `incomeType` set and creates any missing `incomes` array entries. Use this after data migrations.

### Savings Balance Calculation
Account balances are **calculated from contributions**, not stored as a running total:
- Each account has `baseBalance` (manually entered starting balance)
- `balance = baseBalance + sum(contributions) - sum(withdrawals)`
- `recalcAllBalances()` is called after every Pull to prevent drift
- Do NOT increment balances directly — always go through `recalcAccountBalance()`

### Deduplication
Import dedup key: `${date}|${amount}|${card||person}|${normMerchant.substring(0,20)}`  
This is intentionally based on normalised merchant prefix rather than full name, to handle slight variations in bank descriptions between imports.

### Category System
Categories are dynamic — loaded from localStorage, defaulting to `DEFAULT_CATS` if none saved.
- `CATS` — the live array
- `CAT` — an object map `{key: catObject}` built by `rebuildCAT()`
- Always call `rebuildCAT()` after modifying `CATS`
- `saveCats()` writes to localStorage
- Each category: `{ key, label, color, bg, kw:[] }`
- `bg` is auto-generated by `lightenColor(color)` — never store it manually

### Auto-Categorization
`autoCat(merchant)` checks in order:
1. `learned` object (exact match)
2. `learned` object (substring match)  
3. `CATS` keyword rules
4. Falls back to `'misc'`

When user manually reassigns a category, the merchant is saved to `learned` automatically.

## Transaction Object Shape

```js
{
  id: string,           // uid()
  date: 'YYYY-MM-DD',
  merchant: string,
  amount: number,       // positive = expense, negative = refund
  category: string,     // category key e.g. 'groceries'
  person: string,       // e.g. 'Michael'
  card: string,         // e.g. 'RBC Chequing' (more specific than person)
  note: string,
  refund: boolean,
  manual: boolean,      // true if added manually (not from CSV)
  incomeType: string,   // optional: 'salary'|'rental'|'transfer'|'other'
  incomeCategory: string, // optional: category offset for transfers
  savingsAccountId: string, // optional: links to a savings account
}
```

## Income Entry Shape

```js
{
  id: string,
  date: 'YYYY-MM-DD',
  amount: number,
  type: string,         // income type key
  person: string,
  desc: string,         // merchant name or description
  note: string,
  category: string,     // optional: for Transfer/Split type
  fromTxnId: string,    // optional: links back to transaction if flagged from there
}
```

## CSV Import Flow

1. User drops CSV → `openMapper(file)` called
2. `detectHeaders()` checks if first row is a header or data (handles headerless formats like CIBC)
3. `detectBankPreset()` auto-maps columns for known banks (CIBC preset built in)
4. User confirms column mapping + statement type (credit card vs bank account) + card name
5. `doImport()` parses rows, applies sign logic based on statement type:
   - Credit card: positive = expense, negative = refund
   - Bank account: negative = expense, positive = refund/income
6. `autoCat()` assigns categories
7. Deduplication check
8. If mode = `'replace'`: removes existing transactions for that card+period first, then imports fresh
9. Auto-push to Sheets

## Apps Script

The Google Apps Script is displayed in the Settings page (copy button provided). It must be redeployed as a **new version** every time the sheet structure changes. Current sheet columns:

**Transactions**: id, date, merchant, amount, category, person, card, note, refund, manual, incomeType, savingsAccountId, incomeCategory
**Categories**: key, label, color, fixed, budget, keywords (JSON array)  
**Learned**: merchant, category  
**Income**: id, date, amount, type, person, desc, note, fromTxnId, category  
**Savings**: id, name, type, person, balance, baseBalance, goal  
**Contributions**: id, date, amount, accountId, type, person, note, fromTxnId  
**Uploads**: name, count, skipped, person, card, date, mode  
**Trash**: id, date, merchant, amount, category, person, card, note, refund, deletedAt

## Known Quirks & History

- **Income fromTxnId bug**: Was repeatedly broken because the Apps Script income sheet write was missing `fromTxnId` and `category` columns. Always verify these are included when touching income sheet logic.
- **Balance double-counting**: Was caused by `updateAccountBalance()` incrementing on top of already-correct Sheets data. Fixed by making balance always derived from contributions. Never increment balance directly.
- **Pull inflation**: Caused by pulling on top of existing local data. Pull must always fully replace — never merge. Confirm dialog was added to prevent accidental pulls.
- **Date parsing**: RBC chequing uses `M/D/YYYY` format. Amex uses `DD Mon YYYY`. CIBC PDF uses `Mon DD`. The `normDate()` function handles all these — treat month as first for `M/D/YYYY` North American format.
- **CORS on iOS Safari**: Push/pull can occasionally fail on iPhone with "Load failed". Usually resolves on retry. Cloudflare Worker proxy is the permanent fix if needed but hasn't been implemented.

## Code Style Preferences

- No em-dashes (`--`) anywhere
- All CSS in `<style>` block at top
- All JS in single `<script>` block at bottom
- JS sections separated by comments like `// ── SECTION NAME ──`
- Always run `node --check` on extracted JS before shipping
- Changes should be applied to both files unless explicitly personal-only
